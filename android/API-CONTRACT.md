# Mobile API integration — implemented locally, not deployed

The native client now uses `app/api/mobile/v1/[...path]/route.ts` and `lib/mobile-api.ts`. Existing approved-account password verification, SQLite and dashboard records are reused. See [TESTING.md](TESTING.md) for build/install steps and limits. Live VPS deployment and physical-phone tests remain outstanding. Mobile bearer tokens have their own table and are not accepted as web cookies.

Base: an HTTPS origin preconfigured at build time or entered by the tester before sign-in, followed by `/api/mobile/v1`. Server changes are blocked while signed in, while requests are in flight or while trips remain queued. No redirects, cleartext HTTP, embedded credentials, permissive TLS trust managers, or client-supplied employee ownership. Bodies and responses are JSON; successful responses below use HTTP 200. Authenticate every trip operation using `Authorization: Bearer <token>` and derive ownership from the validated token. Tokens are scoped to mobile, expire after one hour, and every operation checks approval and role. Sign-in and authenticated requests are rate-limited. Avoid logging passwords, tokens, or GPS payloads.

| POST path | Request | Required response / behavior |
| --- | --- | --- |
| `/session` | `{phone,password}` | `{accountId,accessToken}` after existing approved-account/password verification. No role escalation. |
| `/session/logout` | `{}` | `{}`; revoke token and end its active trip authorizations. An offline logout clears local credentials immediately; server token/lease expiry bounds remote authorization. |
| `/trips/start` | `{requestId,fix:{lat,lng,accuracy,time}}` UUID and actual fresh GPS fix | `{tripId,leaseMs}`. Atomically create at most one active trip per employee. Idempotency keyed by employee + requestId. Persist the original response identity across lost replies. A replay must not reopen or renew an ended trip: return the original ID with `leaseMs:0` so the client can reconcile it. Validate department and Driver geofence; record server start time and capture deadline. |
| `/trips/lease` | `{tripId}` | `{active,leaseMs}`. Validate ownership, current employment/session and trip policy; issue at most 300000 ms. Atomically extend the authorized capture deadline only while policy permits. `active:false` stops collection when received. |
| `/trips/points` | `{tripId,points:[{seq,time,elapsedMs,lat,lng,accuracy}]}` | `{ackSeq}` equal to the last point in this batch only after the entire transaction commits. Exact retries succeed without duplicate rows or distance. Conflicting replays, sequence gaps, descending sequences/times and invalid fixes fail atomically. |
| `/trips/stop` | `{tripId,stoppedAt,reason}` | `{}` only after idempotent stop commit. Clamp untrusted stop time to the authorized interval; never extend capture authorization. Preserve pre-stop delayed uploads within a defined upload-retention window. |

Use 401 for missing/expired credentials, 403 for revoked authorization, 404 for inaccessible trip, 409 for sequence conflicts, 410 for expired upload windows. Never return a successful acknowledgement for dropped/rejected points. The client retains failed batches; 401/403/409/410 stop local capture and require sign-in/review. Do not silently discard queue data to get past a conflict.

`../lib/mobile-point-ingest.mjs` is mounted behind bearer authentication, approval/role checks, rate limits and a 64 KiB request-body limit. Batches contain at most 100 fixes. Its transaction also updates the existing dashboard trip projection. Capture leases are at most five minutes and never exceed the one-hour token expiry. Upload retention is seven days; trip capture is capped at twelve hours/10,000 points. Schema additions are automatic and additive; VPS deployment remains required. Client clock rollback is rejected, not used to fabricate distance. Client GPS is not cryptographic evidence of employee presence.

Server stop should immediately reject new capture authorizations and record the cutoff. Already queued points captured within an issued lease may be delivered later. A disconnected phone cannot receive an immediate remote stop. The current client polls every 15 seconds while scheduled and caps leases at five minutes; local receipt triggers stop, and elapsed-time checks prohibit further fixes after lease expiry. Android scheduling/sleep can delay timer execution and notification removal. If the business requires immediate remote stop under all network conditions, that requirement is impossible; do not claim it. Exact device timing, including battery saver, remains unverified.

Retention policy, deletion/export procedure, administrative queue-conflict reconciliation, and the company privacy contact are required before rollout. The prototype retains unacknowledged fixes indefinitely in private app storage; acknowledged fixes are deleted locally. Trip metadata remains locally. Define and implement a bounded retention policy without silently losing required travel evidence.
