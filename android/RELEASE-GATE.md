## What exists

- Native Java activity and a non-exported Android `location` foreground service, explicitly started from the visible app after Start trip and disclosure consent.
- Ongoing notification with Stop trip action, plus in-app Stop and Logout controls.
- Coarse + precise runtime permission request and Android 13+ notification permission. Approximate-only or blocked notifications prevents tracking. Permission/GPS loss stops capture; Android may kill the process on revocation, so reopening marks the trip interrupted and never silently restarts it.
- Manifest `FOREGROUND_SERVICE` and `FOREGROUND_SERVICE_LOCATION` declarations. The latter is a normal manifest permission, **not a runtime dialog**. This is Android's required model, despite the original request's runtime wording.
- No `ACCESS_BACKGROUND_LOCATION`. A foreground location service started while the activity is visible can continue when backgrounded. No boot receiver, sticky restart, alarm, or job starts GPS. If future requirements introduce background starts, separately assess Android restrictions and staged permission requests; do not request foreground and background access together.
- Private SQLite queue with transactional sequence assignment; ordered batches, HTTPS bearer authentication, acknowledgement-based deletion, Keystore-encrypted tokens, backup disabled, and a network-constrained upload job that does not collect GPS. No Google Play Services dependency.
- Locally stopped trips retain their queue; logout removes credentials, so the same employee must sign in again to upload remaining records. OS force-stop halts tracking and jobs; reopening schedules uploads without resuming GPS. Job retries after ordinary interruption are best effort; reboot recovery currently occurs on app reopen.
- GPS fixes older than 60 seconds, marked mock, missing accuracy, or worse than 100 m are excluded; no synthetic path is inserted for gaps. These thresholds require field validation.

## Build and signed debug install on a prepared machine

Install JDK 17, Android SDK Platform 35 / Build Tools 35.0.0, Platform Tools, and Gradle 8.11.1 (AGP 8.9.2). Set `JAVA_HOME` and `ANDROID_HOME` locally. From `android/`:

```powershell
gradle wrapper --gradle-version 8.11.1 --distribution-type bin
.\gradlew.bat --version
.\gradlew.bat :app:lintDebug :app:assembleDebug -PptraamApiUrl=https://YOUR-DEPLOYED-VPS-DOMAIN
Get-FileHash .\app\build\outputs\apk\debug\app-debug.apk -Algorithm SHA256
# Use the installed SDK build-tools apksigner.bat:
apksigner.bat verify --verbose --print-certs .\app\build\outputs\apk\debug\app-debug.apk
adb devices -l
adb -s DEVICE_SERIAL install -r .\app\build\outputs\apk\debug\app-debug.apk
```

Gradle signs the debug variant with the local debug key. This is for pilot sideloading, not a production signing identity. Record build logs, source revision, artifact SHA-256 and certificate digest. Do not distribute an artifact built with the default invalid API host. Verify wrapper provenance/checksums before committing it. This project targets API 35 for the pilot; recheck current Play target-SDK requirements before any store submission.
